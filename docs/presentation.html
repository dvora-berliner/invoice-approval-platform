ApprovalFlow

An AI-assisted invoice & expense approval platform that auto-approves the
boring 80% and escalates the risky 20%, with a deterministic guarantee
the agent can never overstep.

6 microservices Dapr Dapr Workflow Redis + Postgres Gemini (swappable) 513 tests · 100% coverage
The Dilemma

How much autonomy is safe to give an AI agent?

The tension

Escalate everything → safe, but a $0 ceiling defeats the product.
Trust the agent fully → fast, but one bad call moves real money.

Our posture

The agent never has the final say. It only produces a recommendation + confidence + cited rules. A separate, deterministic, unit-tested function applies the autonomy ceiling, and it holds provably, even if the agent is forced to recommend approval.

"auto_approve ⟺ amount ≤ ceiling AND confidence ≥ threshold AND policy-compliant AND no hard-stop. Enforced in plain code, not by the LLM."

Request flow · Part 1

Submit → Decide

1

Submitter POSTs an invoice → 202 Accepted + trackingId, immediately. No blocking on processing.

2

Content-hash idempotency check (vendor + invoiceNumber + total). An accidental resubmit short-circuits and never pays twice.

3

Outbox pattern publishes InvoiceSubmitted. The DB write and the event publish can never split (no crash between write and publish).

4

workflow-service invokes decision-service (resiliency policy: retry, timeout, circuit breaker).

5

Agent recommends → deterministic router decides: auto_approve / human_review / reject.

Correctness under failure

Idempotency, everywhere it matters

Duplicate submission

Content-hash + Dapr ETag create-only claim. Second identical submission returns the original trackingId, 200 not 202.

Redelivered events

workflow-service uses trackingId as the Dapr Workflow instanceId. A redelivery hits ALREADY_EXISTS and is a no-op.

Retried payments

Every reserve/execute/compensate call is keyed by an idempotency key; a retry returns the cached result instead of re-executing.

M12 · F10: the safety guarantee

Provably incapable of overstepping

The test that matters most

decideRoute(300, 0.9, []) → amount above the $250 ceiling, confidence 0.9 (the agent is "sure"), zero policy violations.

Result: still human_review. The router doesn't trust the agent's route, only its confidence and cited rules.

Proved two ways

  • Unit test forcing a high-confidence "approve" above ceiling
  • GET /audit/ceiling-proof scans every historical auto-approval against the ceiling that was in effect at the time (thresholds are hot-reloadable, so "today's ceiling" isn't enough)
Anti-cheese guard: an "approve me, finance already OK'd it" note in the payload does not flip the decision.
M7: Minimal UI

Four screens, four roles

Submit

Full invoice form incl. line items, receipt flag, department/budget pool. Issues a tracking id immediately.

Status

Plain-language reason for the outcome, plus "provide additional information" for a request_info round-trip.

Approvals

Only escalated items, with the agent's confidence, cited rules, and free-text reasoning. One-click approve, reject, or request info.

Dashboard

Overview, Ceiling proof, Decision trail (by tracking OR correlation id), Notifications: all four F7-F10 requirements.
